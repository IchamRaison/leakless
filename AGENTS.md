Treat that repository as the source of truth: integrate collaborators’ remote edits before updating it, push relevant note updates there, then refresh this repository’s `vault/` mirror explicitly. Never overwrite team edits with a stale mirror. No automatic sync is configured.

The user requires the Obsidian vault in `vault/` to stay continuously up to date throughout this project. It must let another person or agent understand current progress and resume work without reading chat history.

Before working, read `vault/Accueil.md`, `vault/01 Projet/Passation.md`, and `vault/01 Projet/Tableau de bord.md`. Follow `vault/01 Projet/Continuité du projet.md`.

After every meaningful milestone, decision, experiment, blocker, or change of direction, update the relevant notes and the handoff summary. Do this before handing control back, not only when asked or at the end of the project. Keep current state concise; put historical details in the journal. Distinguish planned, implemented, tested, and verified outcomes, and link evidence to commits, commands, files, or URLs. Record unfinished work and the next concrete action. Never store secrets or invent results.

Keep documentation in French. Include relevant vault updates in implementation commits when practical. This is a project-specific requirement, not permission to publish secrets, unrelated files, or unverified claims.
