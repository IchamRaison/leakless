## Reproduire sur CPU

Depuis la racine de ce checkout, choisir un nouveau dossier `artifacts/baseline`.
Les commandes utilisent la syntaxe de zsh/bash ; sous fish, définir PYTHONPATH avec `set -x`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r configs/baseline/requirements-real-cpu.lock
export PYTHONPATH=src:scripts/timenet:.
.venv/bin/python -m pytest tests/baseline -q
.venv/bin/python -m pipe.tslm.prepare --data-dir artifacts/baseline/data --manifest-dir manifests --output artifacts/baseline/prepared
.venv/bin/python scripts/eval/verify_split_invariants.py --data-root artifacts/baseline/data/extracted --manifest manifests/split_v2.csv
.venv/bin/python -m pipe.baseline.nevil preparer --manifestes manifests --prepare artifacts/baseline/prepared --audio artifacts/baseline/data/extracted --sortie artifacts/baseline/development
.venv/bin/python -m pipe.baseline.train --config artifacts/baseline/development/config.json
```

Réutiliser le téléchargement existant : le pilote d'Icham vérifie les MD5 puis
conserve les archives et les originaux. TimeNet écrit et relit 1 000 records.
La préparation baseline ne lit que les caches train/val. Elle vérifie la parité
numérique avec le callable WAV et conserve toutes les affectations pour l'audit.
Le CSV gelé a SHA256 `7a8716a35284434292314c10da58663e9f848be60edf18db0f98ef9d63d17896`.
Le hash du JSON projeté est distinct, les deux sont enregistrés et contrôlés.

Le run neuf est `artifacts/baseline/rf-v1-001`. Sa `metadata.json` contient
`model_sha256`. Dans **un nouveau processus**, fournir ce hash à la commande :

```sh
.venv/bin/python -m pipe.baseline.nevil livrer --manifestes manifests --prepare artifacts/baseline/prepared --audio artifacts/baseline/data/extracted --developpement artifacts/baseline/development --modele artifacts/baseline/rf-v1-001 --sha256 HASH_MODELE --sortie artifacts/baseline/rf-v1-001/nevil
```

Cette commande vérifie les 208 prédictions validation sauvegardées et leur parité
exacte avec le callable WAV, puis produit 402 scores val/test sans scoring du test.
Le dossier `nevil/` contient les deux colonnes `clip_id,probability_leak`, la
métadonnée requise par le harnais et les prédictions JSONL au contrat Safoan.
Le nom de colonne du harnais n'implique pas que le score soit calibré.
Ne jamais présenter l'évaluation validation à seuil RF fixe comme le résultat
final du harnais : Nevil sélectionne le seuil sur macro-F1 cluster de validation.

## Interface Safoan

```python
from pipe.baseline.audio import Predictor, PredictionError

predicteur = Predictor(chemin_run, hash_modele_connu, artefact_de_confiance=True)
resultat = predicteur.predict(wav_bytes)
payload = resultat.model_dump(mode="json")
```

Même format d'entrée qu'Icham : PCM16 mono 8 kHz, exactement 1 seconde, ≤128 Kio.
Les codes d'erreur sont `model_unavailable`, `unsupported_audio`, `silent_audio`.
`sample_id` est par défaut le SHA256 des octets tronqué à 24 caractères.
Pas de label en entrée, pas de raisonnement ou de confiance calibrée inventés.
Le chargement vérifie le modèle de confiance, les versions de calcul, le DSP et
le code d'agrégation. L'intégration dans l'application reste à Safoan.

## Portée de l'expérience

`split_v2_binary_with_noise_v0`, bruit externe dans le négatif, comme la V0
mécanique d'Icham. Ce protocole ne remplace pas la comparaison principale
site fuite/non-fuite avec bruit externe séparé. Baseline entraînée sur 598 clips,
TSLM V0 décrit par Icham sur 8 clips : une comparaison finale équitable exige
un budget et un périmètre d'apprentissage explicités par Nevil.

Les métriques test des contrôles Nevil étaient déjà publiées et ont été vues
pendant la lecture du contrat. Pas de réglage de modèle sur ces résultats,
mais il serait inexact de parler d'une démarche complètement aveugle.
`benchmark_eligible=false` tant que Nevil n'a pas validé l'évaluation commune.
Groupes de dépendance heuristiques, pas preuve d'indépendance de sites réels.
